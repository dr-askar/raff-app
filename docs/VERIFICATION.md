## فحوصات أندرويد 17 و16KB

[تشغيل الفحص الناجح](https://github.com/dr-askar/raff-app/actions/runs/38785940618) يستخدم نفس ملف 0.3.1 المنشور ونفس SHA-256 أعلاه، دون إعادة بناء أو تغيير توقيعه:

- Android 17 / API 37 / صفحات 4096 بايت: نجح التثبيت وفتح MainActivity وبقاء العملية بعد الانتظار.
- Android 17 / API 37 / صفحات 16384 بايت: نجحت الفحوصات نفسها.
- Android 15 / API 35 / صفحات 16384 بايت: نجحت الفحوصات نفسها.
- نجح فحص LOAD alignment لجميع المكتبات الـ14 بمعماريتي ARM64 وx86_64. تجارب التشغيل تستخدم x86_64؛ لم يُجرّب التنفيذ الفعلي على هاتف ARM64.
- جرى التثبيت الجديد بواسطة ADB دون `-t`؛ لا يختبر ذلك واجهة تثبيت HyperOS أو ترقية نسخة بتوقيع مختلف.

أدوات SDK 12 القديمة كانت تُنشئ target=android-0 لصورة 37.0 وتسبب انهيار SurfaceFlinger قبل تثبيت التطبيق. نجحت الفحوصات بعد تثبيت أدوات 22.0، التحقق من target=android-37.0، تخصيص تخزين 8GB واستخدام عرض software. [بلاغ الأدوات المطابق](https://github.com/actions/runner-images/issues/14484). هذه مشكلة محاكي منفصلة عن السبب غير المعروف لرفض هاتف المستخدم.

لم يتغير ملف APK في هذا الفحص. فحوصات الإصدارات القادمة تتضمن فحص المكتبات وأندرويد 17 بوضع 16KB قبل النشر.
