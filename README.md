# رفّ | Raff

تطبيق Flutter عربي لأندرويد لإدارة أسعار محل صغير، البحث بالباركود، حساب سلة زبون بسرعة، والجرد. الواجهة من اليمين لليسار بألوان زرقاء هادئة.

**هذه نسخة أولية تحتاج تجربة فعلية في المحل قبل الاعتماد اليومي.** يتوفر وضع محلي للتجربة، ووضع Firebase للمزامنة. نجحت اختبارات Flutter الـ63 واختبارات قواعد Firebase الـ17 و`flutter analyze`، وتم بناء APK موحد ونشره، وفُحص تثبيته وفتحه على محاكيات Android 7 و11 و15 و16 و17. راجع [صفحة التنزيل](https://github.com/dr-askar/raff-app/releases/tag/demo-56) و[نجاح نشر الملف](https://github.com/dr-askar/raff-app/actions/runs/38918624792). حالة التحقق مفصلة في `docs/VERIFICATION.md`.

## تشغيل سريع

للتجربة على الهاتف دون تثبيت أدوات برمجة: نزّل [رفّ 0.4.0 مباشرة](https://github.com/dr-askar/raff-app/releases/download/demo-56/raff-0.4.0-universal.apk) وافتحه على هاتف Android 7 أو أحدث، واسمح بالتثبيت من المصدر عند طلب الهاتف. ملف واحد لمعالجات ARM 32 بت وARM64 وx86_64؛ لا يتطلب اختيار نوع المعالج. هذه نسخة محلية ولا تتضمن حساب Firebase للمحل. البناء بوضع release لتقليل الحجم، مع توقيع debug تجريبي؛ يلزم إعداد توقيع دائم قبل اعتماد تحديثات إنتاجية. احفظ نسخة احتياطية من بيانات التجربة قبل الانتقال لإصدار آخر. الكاميرا تحتاج إذناً عند فتح الماسح لأول مرة.

ثبّت [Flutter stable](https://docs.flutter.dev/get-started/install) وAndroid Studio مع Android SDK، ثم شغّل `flutter doctor`. تحتاج Python 3 مرة واحدة لإعداد إذن الكاميرا واسم التطبيق.

من داخل مجلد المشروع، على Linux / macOS أو Git Bash:

```bash
bash scripts/bootstrap.sh
flutter run
```

على Windows PowerShell يمكن تنفيذ الخطوات نفسها مباشرة:

```powershell
flutter create --no-pub --platforms=android,web --org com.raffapp --project-name raff .
python scripts/configure_android.py
flutter pub get
flutter run
```

ملفات Android وWeb القياسية تُولّد من Flutter؛ الكود الموجود في `lib/` محفوظ ولا يُستبدل. لا تستخدم `--overwrite`. إذا أعاد الأمر توليد اختبار تطبيق العدّاد الافتراضي، يحذفه سكربت الإعداد تلقائياً.

يفتح التطبيق دون حساب في **وضع تجريبي محلي** فيه ثلاث مواد. البيانات محفوظة محلياً عبر SharedPreferences؛ هذا الوضع للمعاينة على جهاز واحد ولا يزامن الأجهزة. يمكن قفل واجهة العامل بكلمة سر المدير من الإعدادات. الحسابات الحقيقية لا تتضمن زر تبديل الدور.

لبناء ملف تثبيت تجريبي:

```bash
flutter build apk --debug
```

الملف: `build/app/outputs/flutter-apk/app-debug.apk`. لإصدار فعلي، اضبط توقيع إصدار Android الخاص بك قبل التوزيع؛ لا ترفع مفاتيح التوقيع إلى GitHub.

## الموجود في النسخة

- إضافة مادة وتعديلها وحذفها، تصنيف وبحث بالاسم والباركود، ومنع الباركود المكرر.
- تكلفة بالدولار أو بالسوري، بالقطعة أو الكرتونة، وكمية بالقطعة أو الكرتونة. التخزين النهائي بالقطعة.
- سعر صرف مركزي، ربح عام أو خاص، وسعر يدوي ثابت.
- اختيار نتائج بحث أو مواد محددة وزيادة الربح بنقاط مئوية، مع معاينة وتأكيد.
- سجل تعديلات يتضمن الشخص والوقت والقيمة السابقة والجديدة.
- ماسح كاميرا مع فلاش وتقريب يدوي وإدخال نصي بديل. قراءة واحدة تعود إلى الشاشة حتى لا تتكرر إضافة نفس القطعة داخل جلسة المسح.
- سلة زبون بأعداد ومجموع، دون تسجيل مبيعات أو خصم مخزون. سعر السطر مثبت عند أول إضافة، وزر لتحديث أسعار السلة.
- جرد: العامل يدخل العدد، والمالك يعتمد الجرد ويحدّث الكميات المعدودة. تكلفة القطعة والصرف يُثبتان عند بدء الجلسة.
- استيراد Excel مرن مع معاينة وعزل الصفوف غير الصالحة، وتصدير المواد وتقرير الجرد.
- تنزيل نسخة JSON واستعادتها ضمن الحدود المبينة أدناه.
- دور مدير ودور عامل بصلاحيات قابلة للتخصيص، مع قفل بكلمة سر وقواعد Firestore تتحقق من كل عملية.

## إعداد المزامنة — مرة واحدة

1. أنشئ مشروعاً في [Firebase Console](https://console.firebase.google.com/)، واختر خطة Spark إذا كانت تكفي حجم الاستخدام. المجانية لها حدود؛ راقب عدد القراءات والكتابات والأجهزة. لا يحتاج التطبيق Cloud Functions أو Storage أو فوترة مدفوعة في تصميمه الحالي.
2. أضف تطبيق Android باسم الحزمة `com.raffapp.raff`، وفعّل Authentication ← Email/Password.
3. أنشئ قاعدة Cloud Firestore واختَر موقعاً مناسباً للمحل. انشر محتوى `firestore.rules` من تبويب Rules؛ لا تستخدم قواعد مفتوحة.
4. من Authentication أنشئ حساب صاحب المحل وحساب العامل، وانسخ UID لكل حساب.
5. من Firestore Console أضف هذين المستندين، باستبدال المعرّفات:

```text
stores/main/members/OWNER_UID
  name: "صاحب المحل"      (string)
  role: "owner"           (string)
  active: true            (boolean)

stores/main/members/WORKER_UID
  name: "العامل"          (string)
  role: "worker"          (string)
  active: true            (boolean)
```

6. أضف مستند إعدادات المحل بالقيم الفعلية:

```text
stores/main/settings/current
  rate: 10000             (number — سعر الدولار بعملتك المحلية)
  margin: 20              (number)
  currency: "ل.س"         (string)
  revision: 0             (number integer)
```

7. انسخ `config/firebase.example.json` إلى `config/firebase.json`. ضع إعدادات تطبيق Firebase: `apiKey`, `appId`, `messagingSenderId`, `projectId`. تحصل عليها من إعدادات المشروع أو ملف `google-services.json` الخاص بتطبيق Android. `FIREBASE_APP_ID` لأندرويد يجب أن يكون معرّف تطبيق Android، وليس معرّف تطبيق Web. عند تجربة نسخة Web استخدم ملف إعدادات منفصلاً بمعرّف تطبيق Web.
8. شغّل:

```bash
flutter run --dart-define-from-file=config/firebase.json
```

لبناء APK مرتبط بقاعدة المحل:

```bash
flutter build apk --debug --dart-define-from-file=config/firebase.json
```

يحوي الملف `CLOUD: true` لتفعيل المزامنة؛ لا ينتقل التطبيق تلقائياً إلى التجربة المحلية إذا أخفق إعداد Firebase. لا يطلب المشروع مفتاح خدمة Admin ولا يجب تضمين أي مفتاح خدمة في التطبيق أو المستودع.

إعدادات عميل Firebase ليست مفاتيح إدارية؛ حماية البيانات تعتمد على Authentication وRules. ملف إعداداتك المحلي مستثنى من Git. مشاركة APK تمنح شاشة تسجيل دخول فقط، ولا تمنح عضوية في المحل.

## صلاحيات العامل

العامل يقرأ أسماء المواد والتعبئة والكميات وأسعار البيع. المدير يحدد من صفحة «صلاحيات العامل وكلمة السر» إتاحة التكلفة والصرف والإضافة والحذف والتعديلات والحساب والجرد والسجل لكل عامل. الافتراضي يسمح بالحساب ورؤية الجرد وعدّ المواد فقط. إنشاء حسابات Firebase وإضافتها وتعطيلها ما زال يتم من Firebase Console؛ تخصيص صلاحيات الحسابات الموجودة متاح داخل التطبيق.

المالك يقرأ التكلفة والربح ويجري عمليات الإدارة. تحويل عضو إلى دور آخر أو تعطيله أثناء الاستخدام يخرج حسابه من التطبيق. المستندات المالية الحساسة منفصلة عن المنتجات العامة؛ معامل سعر البيع بالدولار ليس تكلفة الشراء.

## الحساب والمزامنة

```text
سعر تلقائي = تكلفة القطعة بالدولار × (1 + الربح / 100) × الصرف
سعر ثابت   = السعر المحلي الذي أدخله المالك
تكلفة وحدة = تكلفة طرد ÷ محتواه (قطع أو كغ)
قيمة جرد   = الكمية الفعلية × تكلفة الوحدة المحلية المثبتة
```

الربح زيادة على التكلفة، وليس هامشاً من سعر البيع. زيادة الربح الجماعية بمقدار 5 تعني تحويل 20% إلى 25%. تُكتب هذه النسبة كنسبة خاصة للمواد المختارة. الأسعار الثابتة تبقى ثابتة.

تغيير الصرف يكتب مستند إعدادات واحداً؛ كل جهاز يحسب السعر من معامل البيع الموجود بالمادة، دون إعادة كتابة جميع المواد. تغيير الربح العام يعيد حساب معامل المواد التلقائية التابعة للربح العام. المواد غير المسعرة لا تدخل السلة.

Firestore يوفّر قراءة بيانات مخزنة سابقاً على Android عند انقطاع الإنترنت. **التعديلات والجرد في الوضع السحابي تحتاج اتصالاً** لأنها تستخدم معاملات لمنع تعارض الأسعار وإغلاق الجرد أثناء حفظ الأعداد؛ هذه النسخة لا تدعي دعم تعديل مالي كامل دون إنترنت. يظهر تنبيه عند قراءة الكاش. قراءة المواد دون إنترنت تتطلب أن تكون قد فُتحت على الجهاز سابقاً؛ شاشة دخول جديدة قد تحتاج اتصالاً.

تعديل مادة يتحقق من رقم مراجعتها: إذا تعدلت على جهاز آخر، يُطلب إعادة فتحها. تسجيل الجرد لنفس المادة من عاملين يعتمد آخر عدد محفوظ، لذلك وزّع الأصناف بين العمال. الأعداد هي إجمالي المادة الفعلي، وليست إضافات تراكميّة.

## Excel

استخدم `.xlsx`، والصف الأول أسماء أعمدة. لا تحتاج جميع الأعمدة:

| العمود | بديل عربي | السلوك إذا كان فارغاً |
|---|---|---|
| `id` | معرف المادة | معرّف ثابت يضيفه التصدير تلقائياً؛ اتركه فارغاً عند إضافة مادة جديدة |
| `name` | اسم المادة | مطلوب لمادة جديدة؛ يبقى القديم عند تحديث مادة بالباركود |
| `barcode` | الباركود | اختياري؛ احفظه كنص للحفاظ على الأصفار الأولى |
| `category` | التصنيف | عام للمادة الجديدة |
| `pack` | التعبئة | محتوى الطرد: عدد قطع صحيح موجب أو وزن موجب بالكغ؛ الافتراضي 1 |
| `quantity` | الكمية | مخزون بوحدة البيع؛ يقبل الكسور، والافتراضي 0 |
| `unit` | وحدة البيع | `piece` أو `kg`؛ الافتراضي قطعة للملفات القديمة | 
| `cost_per_pack` | تكلفة الطرد | اختياري للاستيراد: يُقسم على `pack` وفق `cost_currency`؛ لا يجتمع مع تكلفة وحدة متعارضة | 
| `cost_usd` | التكلفة | تكلفة الوحدة بالدولار |
| `cost_syp` | رأس المال بالسوري | تكلفة الوحدة بالسوري؛ تملأ هذا العمود أو `cost_usd` فقط |
| `cost_currency` | عملة التكلفة | `USD` أو `SYP`؛ تُستنتج من عمود التكلفة إذا كانت فارغة |
| `margin_percent` | نسبة الربح | تتبع الربح العام للمادة الجديدة |
| `manual_price` | سعر ثابت | سعر محلي اختياري |

الحقول الفارغة تحفظ القيم القديمة عند التحديث. المطابقة بمعرّف المادة الثابت ثم الباركود، ثم الاسم الفريد عندما لا يوجد تعارض باركود. لتغيير اسم مادة بدون باركود، صدّر الملف من الإصدار 0.1.1 أو أحدث وعدّل الاسم مع إبقاء عمود `id` كما هو. الملفات القديمة التي لا تحتوي معرّفاً أو باركوداً لا تسمح باستنتاج الاسم السابق؛ الاسم غير المعروف يضيف مادة جديدة ويحافظ على القديمة. يمكن إضافة مادة جديدة بالاسم وحده وترك المعرف وبقية الحقول فارغة.

الأرقام النصية تدعم الأرقام العربية وفواصل الآلاف المعتادة. الصف غير الصالح أو المتعارض يُذكر باسمه وسببه في تقرير الاستيراد؛ يستمر حفظ الصفوف الأخرى. يمكن تنزيل التقرير إذا ظهرت مشاكل. انقطاع الاتصال أو تغير إعدادات الأسعار يوقف الحفظ مع بيان المواد التي لم تُحفظ. السعر `sale_price` والصرف `exchange_rate` في التصدير للمراجعة فقط ولا يعاد استيرادهما، حتى لا يتحول السعر التلقائي إلى ثابت.

لا يمسح Excel تكلفة أو سعر مادة عند وجود خلية فارغة. لتحويل سعر ثابت إلى تلقائي أو نسبة خاصة إلى عامة، افتح المادة واستخدم خياراتها.

الاستيراد المحلي يحفظ الأصناف على دفعات متتابعة لتقليل الكتابة على الهاتف؛ الدفعة ليست حداً لعدد الأصناف. الاستيراد السحابي يحفظ كل صنف بمعاملة مستقلة. يظهر عداد تقدم وتقرير للأصناف المضافة والمحدثة والمتجاوزة وغير المعالجة وسبب التوقف. اترك التطبيق مفتوحاً أثناء الاستيراد؛ لا توجد معاملة واحدة لكل الملف. التعديل الجماعي يتوقف عند أول تعارض.

## النسخ الاحتياطي وحدود النسخة الأولى

- النسخة المحلية: تشمل كل المواد والإعدادات وآخر 500 حدث والجرد الحالي؛ الاستعادة تستبدل بيانات التجربة المحلية.
- النسخة السحابية المحمولة: تشمل كل المواد والإعدادات وآخر 100 حدث والجرد الحالي. لا تشمل العضويات أو كل أرشيف الجرد؛ هي نسخة بيانات تشغيلية وليست تصديراً كاملاً لكل مستند في Firestore.
- الاستعادة السحابية تدمج المواد بمعرّفاتها وتحدّث الإعدادات، دون حذف المواد الأخرى. لا تعيد السجل التاريخي أو الجرد القديم أو المستخدمين. تحفظ عملية الاستعادة أحداثاً جديدة.
- خزّن ملفات النسخ خارج الهاتف. المزامنة لا تعوّض النسخ الاحتياطي، ولا يوجد جدولة نسخ آلية في هذه النسخة.
- التقريب بالكاميرا يدوي حالياً. التقريب **التلقائي** مؤجل إلى اختبار محرك القراءة على أجهزة المحل.
- باركود واحد لكل مادة في هذه النسخة، دون باركود كرتونة مستقل أو طباعة ملصقات.
- لا يوجد نظام فواتير أو محاسبة أو خصم مخزون عند حساب الزبون.
- حد التعديل الجماعي 100 مادة؛ تغيير الربح العام 140 مادة تلقائية تابعة للنسبة العامة؛ الجرد حتى 400 مادة في المحل. هذه حدود واضحة للنسخة الأولية لتناسب معاملات Firestore وحجم المستند. للمخزون الأكبر يجب تطوير تقسيم الجرد واللقطات قبل الاستخدام.
- المبالغ تستخدم `double` وتُعرض إلى منزلتين. قبل اعتمادها لحسابات مالية رسمية، يلزم تحديد التقريب ووحدة العملة الصغرى؛ التطبيق الحالي أداة تسعير وحساب سريع.

## التحقق

بعد الإعداد:

```bash
dart format lib test
flutter analyze
flutter test
```

لاختبار صلاحيات قاعدة البيانات محلياً، ثبّت Node 22 وJava 21:

```bash
npm install

```

هذه الاختبارات تستخدم محاكي Firestore في مشروع `demo-raff`، ولا تتصل بقاعدة محل حقيقية. تشمل منع العامل من تعديل الأسعار وقراءة التكلفة وترقية دوره، ومنع الجرد السلبي أو المغلق، وحماية أرقام المراجعات. اختبارات Flutter تغطي التسعير والاستيراد والحفظ المحلي والنسخ والجرد والواجهة العربية.

قبل العمل في المحل، جرّب على جهازين: تغير الصرف، مادة بسعر ثابت، باركود جديد ومكرر، إغلاق جرد أثناء تعديله، انقطاع الإنترنت، تصدير واسترجاع نسخة، وسحب صلاحية عامل. اختبر الكاميرا على الهاتف الحقيقي؛ اختبارات الوحدة لا تثبت جودة المسح.

## تحديث 0.2.0: رأس المال بالسوري وصلاحيات العامل

- في المادة، اختر **عملة رأس المال → ليرة سورية** وأدخل تكلفة القطعة أو الكرتونة. التكلفة وسعر البيع التلقائي لهذه المادة لا يتأثران بسعر الدولار. المواد بالدولار تبقى مرتبطة بالصرف، والسعر اليدوي يبقى ثابتاً.
- من **الإعدادات → صلاحيات العامل وكلمة السر**: عيّن كلمة سر المدير أول مرة (6 أحرف على الأقل)، ثم فعّل أو أوقف كل صلاحية. رؤية رأس المال ورؤية نسبة الربح مستقلتان؛ السماح بتعديل أي منهما يفعّل رؤيته فقط، والسماح بالعد يفعّل رؤية الجرد.
- في النسخة المحلية: **قفل التطبيق بوضع العامل**، والعودة للمدير تحتاج كلمة السر. بعد إعادة التشغيل يبدأ التطبيق بوضع العامل إذا كانت كلمة السر محددة. كلمة السر والصلاحيات خارج نسخة بيانات المواد حتى لا يستطيع استيراد نسخة إزالة القفل. كلمة السر مخزنة كقيمة PBKDF2-HMAC-SHA256 مملّحة، وليست نصاً صريحاً. لا يوجد استرجاع محلي لكلمة سر مفقودة؛ احتفظ بها.
- في Firebase: كلمة السر هي كلمة مرور حساب المدير، وتُطلب مجدداً عند فتح الصلاحيات. يمكنك اختيار كل عامل مضاف للمحل وضبط صلاحياته مستقلاً. تُحدّث الصلاحيات عبر مستند العضوية، وتُعاد الاشتراكات وتُمسح بيانات التكلفة المعروضة عند سحب الوصول. انشر `firestore.rules` الجديدة قبل تشغيل النسخة السحابية؛ ملف APK المنشور افتراضياً محلي ولا يزامن الأجهزة.
- يمكن للعامل حسب إذنك: رؤية رأس المال، رؤية نسبة الربح، تغيير الصرف، إضافة/حذف صنف، تعديل الاسم/الباركود/التعبئة/التصنيف، تعديل الكمية، تعديل سعر البيع، تعديل رأس المال وعملته، تعديل الربح، المساومة ضمن حد المادة، استخدام حساب الزبون، رؤية الجرد، إدخال العدد الفعلي، رؤية سجل الأسعار. يمكن منح استرجاع نسخة JSON بصلاحية مستقلة. إنشاء وتصدير النسخ واستيراد Excel والتصدير والربح العام واعتماد الجرد تبقى للمدير.
- حذف الصنف يحرر باركوده ويحافظ على السجل؛ يمنع حذفه إذا كان ضمن جرد مفتوح.
- Excel يدعم `cost_currency` (`USD` أو `SYP`) و`cost_syp` بجانب `cost_usd`. أدخل التكلفة في عمود واحد فقط. الملفات القديمة بدون هذه الأعمدة تبقى مدعومة. التقارير والنسخ الاحتياطية تحفظ العملتين.


## تحديث 0.3.0: الحذف والمساومة واستيراد ملفات الهاتف

- زر **حذف مادة** ظاهر بجوار السعر في قائمة المواد، وثابت أسفل صفحة الصنف، حسب الصلاحية. الحذف يحتاج تأكيداً ويبقى ممنوعاً أثناء جرد مفتوح يشمل المادة.
- **رؤية رأس مال القطعة** و**رؤية نسبة الربح** خياران مستقلان، وكذلك تعديل كل منهما. زر حفظ الصلاحيات ثابت أسفل الصفحة. القيم الجديدة غير الممنوحة تكون مقفلة افتراضياً.
- زر **كلمة السر** أعلى صفحة الصلاحيات يفتح الحالية والجديدة وتأكيد الجديدة. لا يتغير القفل إذا كانت الحالية خاطئة أو التأكيد غير مطابق.
- المدير يحدد **نسبة المساومة %** لكل صنف (افتراضياً 0، من 0 إلى 100). فعّل للعامل **المساومة ضمن النسبة المحددة للمادة**؛ تظهر في سلة الزبون. تخفيض 5% لسعر 10000 يعني 9500 للقطعة. المساومة لا تغير سعر الكتالوج ولا تخصم مخزوناً. تخفيض الحد أو سحب الإذن يزيل الجزء غير المسموح من خصم السلة؛ تحديث أسعار السلة يمسح الخصم السابق للمراجعة.
- Excel يدعم `bargain_percent` أو **نسبة المساومة**. الأرقام العربية وعلامة النسبة مقبولتان. يستخرج الاستيراد قيم الخلايا ويتجاوز التنسيقات المتعارضة التي تولدها بعض تطبيقات الهاتف، مثل 12.0 داخل تنسيق عدد صحيح وتعريف أرقام التنسيقات المدمجة. لا يغير التطبيق الملف الأصلي، والصفوف غير الصالحة تبقى مذكورة في التقرير.
- **للوضع السحابي:** انشر القواعد الجديدة ثم افتح حساب المدير أولاً لترحيل مستندات `pricing` القديمة تلقائياً إلى `costs` لرأس المال و`margins` للربح. المستندات القديمة تبقى ممنوعة على العامل. الترحيل يحفظ المعرفات والقيم الموجودة ولا يكتب فوق مستند جديد موجود. حدّث كل الأجهزة إلى الإصدار نفسه. ملف APK التجريبي لا يفعل Firebase تلقائياً.

## تحديث 0.3.1: توافق التثبيت

مكتبات Android الأصلية مضغوطة وتُستخرج عند التثبيت بدلاً من اشتراط تحميلها مباشرة من APK. حجم الملف الموحد نحو 41.2 ميغابايت، مع بقاء ARM32 وARM64 وx86_64. الحد الأدنى Android 7 (API 24) وفق Flutter المستخدم؛ الإصدارات الأقدم غير مدعومة. نجاح التثبيت والفتح على المحاكيات لا يضمن كل أجهزة Xiaomi أو غيرها، ولا يثبت عمل الكاميرا على هاتف فعلي.

فحص CI يمنع نشر APK قبل نجاح التوقيع وسلامة الأرشيف والمحاذاة والاختبارات وتثبيت/فتح التطبيق على الإصدارات المدعومة. لم يُثبت أن رفض الهاتف السابق سببه واتساب أو مكتبات Android.

**التوقيع التجريبي:** شهادة 0.3.1 تختلف عن 0.3.0؛ التحديث فوق نسخة بتوقيع مختلف سيُرفض. لا تحذف تطبيقاً يحوي بيانات قبل تصدير نسخة احتياطية. إعداد مفتاح إصدار دائم في مخزن أسرار المشروع ما زال مطلوباً قبل اعتماد التحديثات اليومية؛ أُزيلت خطوة كاش المفتاح التي لم تحفظ المفتاح؛ لا يوجد ضمان لاستمراره بين الأبنية التجريبية.

### فحص أندرويد 17 وذاكرة 16KB

[نجح فحص الملف المنشور نفسه](https://github.com/dr-askar/raff-app/actions/runs/38785940618) على محاكي أندرويد 17 بصفحات 4KB ومحاكي أندرويد 17 بصفحات 16KB، وعلى أندرويد 15 بصفحات 16KB. فحص `scripts/check_apk_native.py` يراجع LOAD alignment لكل مكتبات ARM64 وx86_64؛ نجحت المكتبات الـ14. لا يوجد APK خاص بشركة هاتف؛ الملف الموحد 0.3.1 لم يتغير خلال هذه الفحوصات.

فحص الإصدارات القادمة يتضمن أندرويد 17 بوضع 16KB قبل النشر. أدوات SDK مثبتة على 22.0 لتفادي [خطأ بيانات المحاكي android-0](https://github.com/actions/runner-images/issues/14484) عند استخدام صور 37.0. راجع أيضاً [إرشادات أندرويد الرسمية لتوافق 16KB](https://developer.android.com/guide/practices/page-sizes). نجاح هذه الفحوصات لا يثبت سبب رفض هاتف المستخدم للنسخة السابقة، ولا يضمن كل إعدادات HyperOS أو باقي الشركات.


## تحديث 0.3.2: استيراد جميع الأصناف وسعر المساومة

- لا يوجد سقف 30 أو 50 صنفاً للاستيراد. يقرأ القارئ جميع الصفوف في أوراق الأصناف التي تبدأ بعمود اسم أو باركود أو معرف. تبدأ المعاينة بورقة Products إن وجدت، ثم باقي الأوراق. الأوراق الأخرى تُذكر في التقرير إذا احتوت بيانات غير قابلة للمطابقة. العينة المعروضة قبل التأكيد ليست حدّاً للحفظ.
- المطابقة مفهرسة بالمعرف ثم الباركود والاسم الفريد. الصنف المكرر بين الأوراق يُتجاوز مع اسم الورقة ورقم الصف والسبب؛ لا يُكتب مرتين. للصنف الجديد اترك المعرف فارغاً بدلاً من نسخ معرف صنف موجود.
- يظهر عدد الصفوف في الملف وعدد المضاف والمحدّث والمتجاوز والمتعذر حفظه وغير المعالج. يمكن حفظ التقرير حتى عند نجاح الاستيراد. بعد الاستيراد يُمسح فلتر المواد حتى لا يخفي أصنافاً جديدة. البحث في سلة الزبون يعرض جميع النتائج بالتمرير.
- تبقى حدود حماية ذاكرة الهاتف: ملف xlsx حتى 5 ميغابايت، ومجموع محتوى الأرشيف بعد فك الضغط حتى 50 ميغابايت؛ هذه حدود حجم وليست عدداً للأصناف.
- المدير يدخل نسبة المساومة لكل مادة. العامل يرى **سعر المبيع وأقل سعر مسموح** في قائمة المواد وبيانات الصنف والسلة. مثلاً 5000 و2% يعرضان الحد الأدنى 4900. عند إيقاف صلاحية المساومة يكون الحد الأدنى هو سعر المبيع نفسه.
- زر **اختيار سعر للزبون** يطلب مبلغ القطعة، لا نسبة. يبدأ الحساب بسعر المبيع الكامل؛ العامل يختار سعراً بين الحدين ثم يضغط **اعتماد السعر**. الإدخال يدعم الأرقام العربية. تُرفض الأسعار الأقل من الحد أو الأعلى من سعر المبيع، وتُحسب الكمية على السعر المختار. لا يتغير سعر الصنف المحفوظ.
- الحد الأدنى يُقرب لأعلى إلى منزلتين عند الحاجة حتى لا يسمح العرض بتخفيض أكبر من النسبة؛ مثلاً 12.34 و2% يعطيان حداً أدنى 12.10. سحب الصلاحية أو تخفيض حد المساومة يصحح سعر السلة غير المسموح.
- التوقيع ما زال تجريبياً؛ احفظ نسخة JSON قبل الانتقال من إصدار سابق. لا تحذف تطبيقاً يحوي بيانات دون نسخة. إعداد مفتاح إصدار دائم خاص بالمشروع ما زال مطلوباً لضمان التحديث فوق التطبيق القديم.


## تحديث 0.3.3: إصلاح ملف Excel بعد إضافة أصناف

- يعالج القارئ النصوص المكررة داخل فهرس Excel قبل فك الملف، ويحافظ على النص الأصلي لكل خلية. بعض محررات الهاتف تترك مداخل مكررة وغير مستخدمة بعد التعديل؛ كانت مكتبة القراءة تفقد ترتيب المراجع وتفشل قبل المعاينة. لا ترتبط المشكلة بتجاوز 100 صنف.
- يغطي الاختبار ملفاً صناعياً يحاكي 113 صنفاً و192 مدخلاً نصياً مكرراً، واستيراد 1200 صنف من ورقة واحدة مع التحقق من جميع المواد بعد إعادة فتح التخزين. لا تحتاج تقسيم الورقة أو معالجة النصوص يدوياً.
- عند إضافة صنف جديد، اترك id فارغاً ولا تنسخ معرف مادة أخرى. الحقول الاختيارية الفارغة مقبولة. حد الحجم يبقى 5MiB للملف و50MiB بعد فك الضغط لحماية ذاكرة الجهاز.
- توقيع APK تجريبي وقد يختلف عن السابق. لا تحذف نسخة فيها بيانات قبل تصدير JSON والتحقق من وجوده خارج التطبيق. بعد استعادة المواد، اضبط كلمة سر المدير وصلاحيات العامل من جديد.


## تحديث 0.4.0: سعر الطرد، الكيلوغرام، وGoogle Drive

- شاشة المادة تبدأ بسعر تكلفة الطرد ومحتواه. مثال: 24 دولاراً ÷ 12 قطعة = دولارين للقطعة؛ 25000 ل.س ÷ 12.5 كغ = 2000 ل.س للكغ. يمكن تبديل الإدخال إلى تكلفة الوحدة دون تغيير معناها. السعر النهائي والربح والمساومة تبقى محسوبة للوحدة المختارة.
- اختر وحدة البيع قطعة أو كغ. الكمية والوزن في الجرد والمخزون تقبل الكسور. مسح باركود مادة وزن يطلب الكمية، واضغط الكمية في السلة لتعديلها. 0.125 كغ بسعر 5000 للكغ = 625. عدد القطع في السلة صحيح موجب. لا تخصم السلة المخزون. تغيّر وحدة مادة موجودة بالسلة يتطلب حذفها وإضافتها مجدداً قبل تحديث الأسعار، حفاظاً على معنى الكمية.
- صلاحية `restoreBackup` مستقلة ومقفلة افتراضياً. تسمح باسترجاع المواد والأسعار والإعدادات حتى لو لم يكن العامل يملك حق تعديلها منفردة، وتبقى كلمة سر المدير والصلاحيات محفوظة خارج النسخة. لا تمنحه قراءة التكلفة داخل التطبيق أو تصدير النسخة. **ملف JSON نفسه يحتوي تكاليف**؛ امنح الاسترجاع لمن تسمح له باستلام الملف.
- قسم Google Drive يستخدم نافذة ملفات Android: افتح قائمة المواقع واختر Drive، ثم المجلد للحفظ أو الملف للفتح. يدعم Excel وJSON ويتطلب Drive مثبتاً ومسجل الدخول. هذه عمليات يدوية، وليست مزامنة تلقائية أو ربط حساب Google داخل رفّ. الوصول يقتصر على الملفات التي تختارها. تجربة Drive بحساب حقيقي على الهاتف مطلوبة؛ لا تغطيها محاكيات التثبيت.
- في Excel يبقى السعر المصدّر تكلفة الوحدة، لتستطيع تعديله وإعادة استيراده كما في السابق، ويحفظ عمود unit نوعها. يمكنك استيراد تكلفة طرد من ملف خارجي بعمود cost_per_pack مع pack وcost_currency؛ لا تكتب تكلفتين متعارضتين في الصف.
- النسخ القديمة تبقى متوافقة ووحدتها الافتراضية قطعة؛ راجع الأصناف التي تريد بيعها بالكيلوغرام وحدد وحدتها وسعرها وكمية مخزونها من بيانات المادة.
